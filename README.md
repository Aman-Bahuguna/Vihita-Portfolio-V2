# Vihita Khurana — Spaces with soul

The completed visual revisions are documented in `REDESIGN.md`. The home opens with the interactive 3D room and continues through matching expertise, software-toolkit, gallery, introduction, contact, and footer sections. The original below-the-fold-only 3D loading description below is historical. The home, Designer, and Selected Work archive use ink, ivory, acid yellow, and bold sans-serif typography. Individual project-detail pages retain their existing presentation.

A continuous, room-inspired portfolio built with strict TypeScript, React, Vite, React Router, CSS Modules, GSAP/ScrollTrigger, Lenis, Motion, and a lazy React Three Fiber room study.

## Setup

```sh
pnpm install --frozen-lockfile
pnpm dev
```

No credentials or environment inputs are required. Contact links use the email and phone from the supplied résumé; this site does not pretend to submit a form.

```sh
pnpm typecheck
pnpm build
```

For local performance checks, run `pnpm build` followed by `pnpm preview`. This serves the optimized production files; `pnpm dev` includes development tooling and is not representative of the deployed site's performance.

Vite + React Router was chosen over a runtime Next.js application because this portfolio needs no server, private integration, or database. It is a statically deployable client-side experience. Configure the host to rewrite unknown application routes to `index.html`; asset and PDF requests should retain their normal paths. The Figma lifecycle scripts use the static adapter and `dist` output.

### Hosting, refreshes, and recovery

Publish **the contents of `dist`**, generated by `pnpm build`, not the source folder. The app uses browser-history routes, so the host must serve `index.html` when a visitor opens or refreshes a page such as `/projects` or `/about`.

- **Netlify / Cloudflare Pages:** `public/_redirects` is copied into `dist` and supplies the SPA fallback.
- **Vercel:** the root `vercel.json` rewrites page URLs without rewriting asset/file requests. Keep this file when deploying from the repository.
- **Apache / shared hosting:** the build includes `.htaccess`; enable `mod_rewrite` and allow overrides. Upload hidden files too.
- **Nginx:** configure `location / { try_files $uri $uri/ /index.html; }` in the host’s site configuration.
- **Other static hosts:** configure an SPA fallback to `/index.html`. The build also emits `404.html` with the compiled app, for hosts that support a custom 404 document. A 404 fallback can render valid deep links but still returns HTTP 404; prefer a 200 rewrite for correct indexing.

These defaults assume deployment at the domain root. A subdirectory deployment needs a matching Vite base and router basename. Server outages and host-generated error pages cannot be intercepted by React; the host must load the app first.

Unknown routes and missing project slugs display the architectural 404 screen. React rendering and lazy-page loading failures display a separate recovery screen. Both offer a full-page **Back to the entrance** link, which also clears a failed app state. A human-readable `/sitemap`, linked from both footers, lists main pages, collection filters, and all project detail routes directly from the project data. Verify refreshing `/projects`, `/about`, and a project URL on the published host after uploading.

```text
    ui/           Local design-system primitives, navigation, modal, controls
  data/           Verified designer details, typed project archive, collections
  features/
    about/        Spring-driven, keyboard-accessible hanging designer card
    projects/     Project cards, image pan/zoom, original-drawing comparison
  hooks/          Motion preference, scoped animation cleanup, page titles
  lib/            Shared utilities as needed
  pages/          Home, Projects, ProjectDetail, About, NotFound
  styles/         Global reset and design tokens
  types/          Project, image, drawing, hotspot, and collection types

```

## Add a project, especially Residential

1. Add optimized images and optional PDF drawings under `public/assets`.
2. Add a record in `src/data/projects.json`, following `Project` in `src/types/project.ts`:

```json
{
  "slug": "a-new-home",
  "title": "A new home",
  "category": "residential",
  "scope": "Residential interior",
  "description": "Your verified project description.",
  "status": "rendered",
  "images": [{
    "src": "/assets/a-new-home-01.webp",
    "thumb": "/assets/a-new-home-01-thumb.webp",
    "alt": "A specific description of this supplied view",
    "width": 1600,
    "height": 1200,
    "source": "Original asset filename"
  }],
  "drawings": [],
  "sourceFolder": "Your original source folder"
}
```

3. The Residential collection automatically replaces its explicitly labeled empty state when it has projects. Category navigation and project detail routing are data-driven. Add `hotspots` or an honest `comparison` only when corresponding assets exist. See the Abhishek record for an actual existing/proposed drawing pair.
4. Curate home highlights through `selectedSlugs` in `src/data/projects.ts`.

The category parser validates supported categories. All four category names are supported. Collection copy and placeholder messaging live in `src/data/collections.ts`.

Supplementary drawing projects can also appear in Extra Work by setting `showInExtraWork: true` while retaining their primary Commercial or Residential category. `projectsInCollection` drives both archive listings and category counts without duplicating records, routes, or assets. Extra Work keeps its selected-six preview and expands to the complete drawing collection.

## Performance and accessibility

- All 28 renders and both portraits have metadata-stripped WebP derivatives. Project cards use separate 680px thumbnails; full views are loaded as needed. PDF previews are rasterized first pages; originals are linked, not embedded.
- GSAP owns the **single Lenis RAF** on mouse/trackpad devices. Touch devices keep native momentum scrolling while GSAP follows the same scroll position. ScrollTriggers are scoped and reverted on unmount. `ScrollManager` centrally refreshes after route content, fonts, or actual layout-size changes, rather than recalculating every trigger for each image load.
- The fine-pointer cursor is a theme-colored point with an eased halo and pill-shaped View/Drag/Pull labels. Pointer events are batched to display frames, unchanged state is not rewritten, and its animation stops when settled. Explicit modal open/close notifications place it in the correct top layer without observing all DOM changes. Touch, native input fields, and reduced motion retain native pointers.
- The hero's 3D chunk is lazy-loaded after a 1.6-second entrance-animation window and an idle opportunity, only while the entrance remains visible. Its supplied FBX and 4K textures are converted offline into a ~622 KiB GLB with embedded WebP textures and three mesh batches. It uses demand rendering, capped 1.5 DPR, no real-time shadows, and pauses rendering offscreen and in hidden tabs. A small static preview covers loading and devices without WebGL. It does not run a permanent render loop.
- Desktop gallery pinning becomes native scroll-snap on smaller screens, with GSAP image parallax, entry reveals, a working progress track, and swipe/arrow navigation. The floor-plan drawing also has a dedicated unpinned touch timeline. Reduced-motion mode removes these animations without hiding content.
- System reduced-motion preference is respected; the visible control lets visitors explicitly override it. The site is silent: no audio toggle, audio context, or generated sound effects.
- Native modal focus management, Escape-to-close, keyboard zoom and image navigation, labeled hotspots, an accessible comparison range, keyboard movement of the hanging card, semantic headings, and a skip-to-content link.
- All UI surfaces use flat color tokens. No CSS gradients.
- Both typefaces are self-hosted WOFF2 files, with licenses in `public/fonts`; the initial experience makes no external font or image requests. Site branding and all eight toolkit marks use local, high-resolution PNGs; provenance and regeneration are in `public/logos/SOURCES.md`.
- Core browsing, gallery navigation, project PDFs, and contact remain available when motion is reduced.

See `TESTING.md` for the exact viewport, interaction, and deployment checks, plus the limits of the performance verification.

Check every referenced local asset with `node scripts/check-assets.mjs`. Add the preview or published origin as an argument to also check HTTP responses and image MIME types, for example `node scripts/check-assets.mjs http://localhost:3000`.
